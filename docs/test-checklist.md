# 테스트 체크리스트

> 마지막 업데이트: 2026-05-10
> 환경: 로컬 개발 (`http://localhost:5173` → `http://localhost:8000`)

---

## 사전 준비

- [ ] 백엔드 서버 실행 (`npm run dev` in `/backend`)
- [ ] 프론트엔드 서버 실행 (`npm run dev` in `/frontend`)
- [ ] PostgreSQL 실행 중
- [ ] Redis 실행 중 (없으면 Drive 동기화만 비활성화됨)
- [ ] `.env` 파일 확인 (`VITE_API_BASE_URL`, `VITE_KAKAO_MAP_KEY` 등)
- [ ] Google OAuth2 앱 설정 확인 (callback URL)
- [ ] 테스트용 Google 계정 3개 준비: `USER`, `HOST`, `ADMIN` 역할

## 1. 인증 (Auth)

### 1-1. Google OAuth2 로그인

- [ ] `/login` 페이지 진입 — Google 로그인 버튼 노출
- [ ] Google 로그인 버튼 클릭 → Google 계정 선택 화면으로 이동
- [ ] 계정 선택 후 `/oauth2/callback` 경유 → `/` 로 리다이렉트
- [ ] 로그인 후 BottomNav에 내 프로필 아이콘/이미지 표시
- [ ] 최초 로그인 시 닉네임 자동 생성 확인 (Google 이름 기반)
- [ ] `love_device_id` localStorage 저장 확인
- [ ] `access_token`, `refresh_token` httpOnly 쿠키 저장 확인 (DevTools → Application)

### 1-2. 토큰 자동 갱신

- [ ] `access_token` 만료(1시간) 후 API 요청 시 자동 refresh
- [ ] refresh 성공 후 원래 요청 재실행 확인
- [ ] `refresh_token`도 만료된 경우 → `/login` 리다이렉트

### 1-3. 로그아웃

- [ ] `/me` → 로그아웃 버튼 클릭
- [ ] 쿠키 삭제 확인 (`access_token`, `refresh_token`)
- [ ] `/login` 으로 리다이렉트
- [ ] 로그아웃 후 `/me` 직접 접근 → `/login` 리다이렉트 (ProtectedRoute 동작)

### 1-4. Rate Limiting

- [ ] `/api/auth/login` 을 15분 내 10회 초과 호출 → 429 응답
- [ ] 429 응답 메시지: "요청이 너무 많습니다. 잠시 후 다시 시도해주세요."

### 1-5. CSRF 토큰

- [ ] 상태 변경 API(POST/PUT/PATCH/DELETE) 요청 전 `GET /api/auth/csrf` 자동 호출 확인
- [ ] CSRF 토큰 없이 상태 변경 API 직접 호출 → 403 응답

## 2. 사용자 (User)

### 2-1. 내 정보 조회

- [ ] `/me` 진입 시 프로필 카드 표시 (닉네임, 이메일, 프로필 이미지)
- [ ] 프로필 이미지 없으면 기본 아이콘 표시

### 2-2. 프로필 수정

- [ ] `/me/edit` 진입 — 현재 닉네임 프리필
- [ ] 닉네임 변경 저장 → `/me` 리다이렉트 후 반영 확인
- [ ] 중복 닉네임 입력 → 에러 메시지 표시
- [ ] 프로필 이미지 업로드 → 미리보기 후 저장, 화면 반영
- [ ] 프로필 이미지 삭제 → 기본 아이콘으로 변경

### 2-3. 회원 탈퇴

- [ ] `/me` → 회원 탈퇴 메뉴 접근
- [ ] 탈퇴 확인 다이얼로그 표시
- [ ] 탈퇴 후 쿠키 삭제 및 `/login` 리다이렉트
- [ ] 탈퇴 계정으로 재로그인 시도 → (30일 내 soft delete 계정 처리 확인)

## 3. 청첩장 (Wedding)

### 3-1. 청첩장 생성

- [ ] `/create` 진입 (비로그인 시 `/login` 리다이렉트 확인)
- [ ] **Step 1 - 히어로 이미지**: 이미지 최소 1장 업로드, 미리보기, 순서 변경
- [ ] **Step 2 - 신랑신부 정보**: 신랑 이름·연락처·부모님·계좌, 신부 동일
- [ ] **Step 3 - 일정·장소**: 날짜, 시간, 예식장명, 주소 입력
  - [ ] 카카오 주소 검색 API 동작 확인
  - [ ] 주소 선택 후 카카오 지도에 핀 표시
- [ ] **Step 4 - 추가 정보**: 드레스코드, 안내 메시지 (선택사항)
- [ ] 모든 단계 완료 후 제출 → `/` 로 리다이렉트
- [ ] HOST 계정으로 청첩장 생성 후 `/me` 에서 내 청첩장 섹션 확인

### 3-2. 청첩장 조회 (공개)

- [ ] `/` 진입 → 최신 청첩장 자동 로드
- [ ] `/:weddingId` 진입 → 해당 청첩장 로드
- [ ] InfoTab: 신랑신부 이름, 결혼식 일시, 장소, 주소 정상 표시
- [ ] InfoTab: 카카오 지도 핀 정상 렌더링
- [ ] InfoTab: 계좌번호 및 은행 정보 표시
- [ ] HeroImage 슬라이드 자동 전환 및 수동 스와이프

### 3-3. 청첩장 수정

- [ ] InfoTab 수정 버튼 → `/edit?weddingId=` 이동 (소유자만 노출)
- [ ] 기존 데이터 프리필 확인
- [ ] 일부 필드만 수정 후 저장 → 정상 반영

### 3-4. 청첩장 삭제

- [ ] InfoTab 삭제 버튼 → 확인 다이얼로그
- [ ] 삭제 후 청첩장 목록에서 사라짐 (soft delete)
- [ ] 다른 사용자의 청첩장 삭제 시도 → 403

### 3-5. 권한 분기

- [ ] USER 계정: 수정/삭제 버튼 미노출
- [ ] HOST 계정 (본인 청첩장): 수정/삭제 버튼 노출
- [ ] ADMIN 계정: 모든 청첩장에 수정/삭제 버튼 노출

## 4. 참석 의향서 (RSVP)

### 4-1. 참석 의향서 작성 (비로그인 게스트)

- [ ] RsvpTab → 참석 의향서 폼 표시
- [ ] 이름, 측(신랑측/신부측), 인원, 식사 여부 입력 후 제출
- [ ] 제출 후 내 RSVP 카드 표시
- [ ] 같은 브라우저(sessionId 유지) → 기존 RSVP 조회 확인

### 4-2. 참석 의향서 수정

- [ ] 기존 RSVP 수정 버튼 클릭 → 폼 프리필
- [ ] 수정 저장 → 변경 내용 반영

### 4-3. 참석 의향서 취소

- [ ] 내 RSVP 취소 버튼 → 확인 후 삭제
- [ ] 다시 폼 입력 가능 상태로 복귀

### 4-4. 관리자 통계 (HOST/ADMIN)

- [ ] HOST 로그인 후 RsvpTab → 통계 패널 표시
- [ ] 전체 참석 인원, 신랑측/신부측 분리 통계 확인
- [ ] 식사 선택 현황 확인
- [ ] 전체 RSVP 목록 페이지네이션 동작

### 4-5. CSV 내보내기

- [ ] `/api/rsvp/export?weddingId=` 호출 → CSV 파일 다운로드
- [ ] CSV 내용 확인 (이름, 측, 인원, 식사, 연락처 등)

## 10. 보안 & 엣지 케이스

### 10-1. 인증 미들웨어

- [ ] 인증 필요 API를 토큰 없이 호출 → 401
- [ ] HOST 전용 API를 USER 권한으로 호출 → 403
- [ ] 만료된 access_token → refresh 후 재시도 (자동)
- [ ] 만료된 access_token + refresh_token → 로그아웃 처리

### 10-2. 입력 유효성 검증

- [ ] 필수 필드 비워서 폼 제출 → 에러 메시지 표시
- [ ] 이미지 외 파일 업로드 시도 → 에러 처리
- [ ] 너무 긴 텍스트 입력 → Zod 유효성 검증 에러

### 10-3. 다중 기기 (디바이스 제한)

- [ ] 동일 계정으로 6개 기기 로그인 → 가장 오래된 기기 자동 제거

### 10-4. API 응답 포맷

- [ ] 성공 응답: `{ status: { code: 200, message: "OK" }, data: { ... } }` 구조
- [ ] 에러 응답: `{ status: { code: 4xx, message: "..." }, data: null }` 구조

### 10-5. 소프트 삭제

- [ ] 삭제된 청첩장/사용자 API 조회 시 미노출 (deletedAt 필터링)
- [ ] 삭제된 데이터에 직접 ID로 접근 → 404
